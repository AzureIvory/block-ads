# 根除任务（第一版）

`main.go` 原有的进程筛选、名单匹配、20 秒去重、`fuck` 结束进程及旧日志格式保持不变。每次原逻辑确认命中并调用 `fuck` 后，向根除队列提交 **一条** 带 ID 的 `HitEvent`；同 ID 重复提交在当前运行中去重。入队不等待清理线程，命中不会因为固定队列容量而丢弃。启动扫描和 ETW 共用这个入口。

工作线程按 `退出确认 → 证据 → 持久化扫描 → 隔离 → 结果记录` 处理。为了获取已加载 DLL，分发入口在原有结束动作前尝试模块快照，并从同一进程句柄读取创建时间与镜像路径，再记录目标文件身份；快照失败不影响结束进程和入队。当前 PID 的创建时间比 ETW 事件时间晚超过 20 毫秒时，后续根除拒绝使用该身份；20 毫秒内的时钟差和极快复用仍需真实 ETW 测试评估。新进程的模块表可能尚未初始化，因此 DLL 证据可能缺失。

## 自动处理范围

- EXE：必须是已命中的完整路径、文件身份与命中时一致、可读取 SHA-256，且实际文件位于当前用户的 AppData 目录。默认复制进 `eradication/quarantine/`，校验副本和原件哈希后删除原路径。
- DLL：必须在命中进程的模块快照中、与 EXE 同目录、位于当前用户 AppData、不是 Microsoft 签名，并与 EXE 签名一致或位于命中的目录规则下；如观察到其他进程也加载该 DLL，则不自动隔离。
- 持久化：只有目标精确指向上述高置信度文件，才清除 Run/RunOnce、Startup 文件夹快捷方式或计划任务。服务只扫描与备份，标为 `experimental_review`，默认不删除。任务名、服务名和父目录名本身不用于判定。
- 其他位置的 EXE、低置信度 DLL、无法解析的启动命令只记录供检查，不自动删除。

每次任务在 `eradication/cases/<id>.json` 留下结果。处置前先保存 `<id>-plan.json`；计划任务 XML、快捷方式及服务注册表项另存于 `eradication/backups/<id>/`。快捷方式的 target、arguments、working directory 分开记录，并保留原始 `.lnk` 文件。隔离失败或即时校验失败记为 `pending`；即时处置成功记为 `pending_verification`，直到完成持续观察及重启后验证才能称为根除完成。同一管理器内的处置串行执行；隔离后的文件有稳定 artifact ID 与独立归属记录，多个 PID 命中同一文件时，各 case 引用该记录，实际文件只隔离一次。

处置结束后会独立只读核对：原命中 PID 的创建身份及退出状态、进程快照中是否仍有相同 EXE 完整路径、已隔离/共享关联文件的原路径是否缺失，以及已移除 Run/Task/Startup 的精确位置是否仍为空。PID 已被复用时只记录原进程已退出，不操作新进程；同名候选进程无法查询完整路径时记为无法确认。每项检查写入独立 Action Journal，case 的 `verification` 保存范围、时间、operation ID、结果与证据；日志写入失败记为 `incomplete`，不能算通过。发现原路径或持久化位置重新占位、或同路径进程再运行，会保留现场并记为 `partial_failure`，不会凭这次观察再次删除或终止。占位内容不一定来自原软件，归因仍待后续调查。即时核对通过仍为 `pending_verification`；持续观察和重启后验证尚未完成。当前按删除用途优先推进这些验证，额外恢复扩展暂缓。

原件删除遇到共享冲突时，先用 Windows Restart Manager 枚举占用者。只有占用进程的创建时间、镜像路径与文件 identity 都对应命中的 EXE，才会终止并确认退出；随后重试删除。其他占用进程不会被终止。仍被占用时尝试登记 `MoveFileEx(MOVEFILE_DELAY_UNTIL_REBOOT)`，case 和 artifact 保持 `pending_reboot`，原件仍存在，不能计为已隔离。登记通常需要管理员或 LocalSystem 权限；失败则保持 `pending`。重启后的实际删除尚需复查；登记只证明请求已写入系统，且路径在重启前被替换时有误删风险。

## 恢复

使用 `block-ads.exe --restore-case <id>` 从隔离区恢复 EXE/DLL，并恢复可自动重建的 Run 项、Startup 快捷方式和计划任务。共享 artifact 的关联 case 先执行该命令释放引用，owner case 在引用释放后执行实际恢复；已有不同内容的原路径不会被覆盖。服务备份保留为 `.reg` 供人工检查，当前没有自动服务处置，也无需自动恢复服务。

待重启删除的 case 暂不允许恢复，因为恢复前必须先安全取消系统中尚未执行的删除请求。此版本不会自动接管文件所有权或更改 ACL。其他隔离失败会在 case 结果中保留原因。
