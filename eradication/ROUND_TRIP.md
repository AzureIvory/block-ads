# 隔离与恢复的中断边界

这是 P2 往返测试对应的当前行为记录。P3 加入 Action Journal 前，不能把跨步骤操作视为事务，也不能仅凭最终 case 状态推断每一步已经完成。

| 中断位置 | 磁盘上可能看到的状态 | 当前处理 |
| --- | --- | --- |
| 隔离副本写入或校验前 | 原文件仍在；可能有 `.artifact-*` 临时文件 | 原文件未删除；临时文件可清理 |
| 隔离副本发布后、删除原件前 | 原文件与隔离副本同时存在，case plan 已写入 | 不应宣称完成；核对两边哈希与文件 identity |
| 删除原件后、归属记录写入前 | 原文件缺失，隔离副本存在，归属记录可能缺失 | 当前不能自动重试或自动恢复；P3 必须由 intent 和实际状态重建 |
| 归属记录写入后、最终 case 写入前 | 原文件缺失，归属记录存在，case 仍可能只有 plan | 当前需要人工核对；P3 必须完成提交或安全回滚 |
| 恢复副本写入或校验前 | 原路径缺失；可能有 `.restore-*` 临时文件 | 不恢复启动项，保留隔离副本 |
| 恢复文件发布后、归属记录更新前 | 原路径已有文件，但 case 仍显示隔离 | 当前重试会拒绝占用路径，即使哈希相同；P3 必须证明文件来源后才能提交 |
| 归属记录更新后、case 写入前 | 文件已经恢复，case 可能仍显示旧状态 | 当前需要人工核对；P3 应通过日志重建 |
| 文件恢复失败 | 原路径被占用、哈希不符或写入失败 | case 为 `partial_restore`，保持持久化项已移除；修正障碍后可重试 |

隔离副本和恢复临时文件在发布前完成写入、同步和哈希校验。恢复文件使用不带覆盖标志的 `MoveFileEx`，即使检查后出现新的占位文件，也不能覆盖它。恢复启动项只在所有待恢复文件均成功后执行。

Run/RunOnce 恢复在提交结果前重新读取值内容与 `REG_SZ`/`REG_EXPAND_SZ` 类型；同内容但不同类型或不可读取的现有值会拒绝恢复。Startup 快捷方式同样通过不覆盖目标的 `MoveFileEx` 发布，并在提交前核对目标和备份哈希。恢复 intent 保留精确位置、关联文件及值类型或备份哈希；只读恢复检查不会因内容匹配而自动补写提交。动作结果已提交、case 持久化项仍显示已删除的窗口也会报告人工检查。Task 恢复目前只补充 intent 中的备份身份，尚未完成完整 XML 结果校验及恢复现场核对。注册表读取与写入之间仍无原子 compare-and-set 保证，其他进程并发写入的竞态还需后续处理。

P3 已对隔离与恢复副本的复制、哈希校验、发布、原件删除、归属记录写入、持久化删除、归属恢复、持久化恢复、共享引用增减及最终 case 提交写入独立的 intent 与结果文件。若动作完成后进程崩溃，intent 会留在 `eradication/journal/<case_id>/`。下次启动会只读核对原路径、隔离副本与恢复临时副本的哈希、文件 identity、归属记录、Run/Task/Startup 删除现场及最终 case 快照；已提交但缺少 case 的共享引用，以及已复制但未发布的恢复副本也会报告。同一路径的新命中会留下待处理 case，避免重复删除。即使原路径已有同哈希文件，也不能由此证明恢复动作已安全完成。当前检查不会自动重试或回滚；“原件已删但归属记录未写”和“文件已恢复但归属记录未更新”两个窗口仍需完整的 case 与 journal 重建规则。
